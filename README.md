# 1c-vibe

**ИИ-агенты для 1С-разработки** (ЦИТ ТюмГУ). Агент берёт задачу из Jira,
сам готовит ветку в git, правит код конфигурации (XML/BSL), проверяет себя
BSL-линтером и присылает Merge Request в GitLab с комментарием в Jira.
**Человек ревьюит и мержит** — агент никогда не пишет в основную ветку и
не выполняет необратимых действий.

Статус: цикл «Jira → код → MR → комментарий» **работает и проверен на
живом контуре** (реальные MR и комментарии агентов в демо-проекте:
`gitlab.utmn.ru/rd/1c-ai/1c-vibe-demo`).

---

## Как этим пользоваться (режим работы, решение владельца 2026-10-14)

Основной и поддерживаемый режим — **локальная установка из клона этого
репозитория**: git, Node.js и агентская среда (DeepSeek Harness, `dsh`)
на компьютере разработчика, без Docker и без серверов. Всё, что нужно
тулкиту, ставится за один вечер по инструкции:
**[docs/onboarding.md](docs/onboarding.md)** — начни с неё.

Платформа [agctl](https://github.com/arijjia/agctl) (саморазворачивающиеся
изолированные рабочие места на общем сервере) — **целевая инфраструктура
будущего этапа**: когда она будет внедрена в контуре ЦИТ, отдел переедет
на неё без изменений этого тулкита. Историческое решение «только через
agctl» от 2026-10-07 развёрнуто решением владельца 2026-10-14
(обоснование — agctl-hq, §11.1.1).

## Быстрый старт (кратко; подробно — docs/onboarding.md)

```bash
# 0. Инструменты (один раз): git, uv, Node.js 20+, Java 11+ (для линтера)
#    macOS:   brew install git uv node@22 openjdk@17
#    Windows: winget install --id Git.Git; winget install OpenJS.NodeJS.LTS
#             winget install Microsoft.OpenJDK.17   + uv с astral.sh

# 1. Репозиторий и окружение
git clone https://github.com/arijjia/1c-vibe.git
cd 1c-vibe/mvp
uv sync                                   # создаст .venv, Python ставится сам

# 2. Доступы к Jira и GitLab
cp .env.example .env                      # заполни JIRA_*, GITLAB_*, DEMO_PROJECT

# 3. Агентская среда
npm install -g @deepseek-ai/dsh
dsh web                                   # откроется http://127.0.0.1:3080

# 4. Модель: провайдер utmn (LiteLLM) — см. onboarding.md, раздел 4
```

Дальше работа одной фразой агенту: **«пофикси INTAIDEV-2 и сделай MR»** —
и ревью MR в GitLab.

## Проверка, что всё работает

Пять уровней — от «окружение живо» до «агент сдал задачу» (полная версия с
командами и ожидаемыми результатами — [docs/onboarding.md](docs/onboarding.md),
раздел 8):

| Уровень | Что проверяем | Зелёный результат |
|---|---|---|
| 1 | доступы и тулкит | `whoami` отвечает; задача читается; тесты **14 passed**; линтер работает |
| 2 | ручной цикл без агента | `publish.py --prepare` → правка → `publish.py` → **MR в GitLab + комментарий в Jira** |
| 3 | цикл с агентом | фраза «пофикси `<KEY>` и сделай MR» → ветка `agent/<KEY>`, линт чист, MR создан, Jira прокомментирована |
| 4 | новый человек/компьютер | `scripts/cleanroom-dsh.sh` — чистая комната поднимается с нуля |
| 5 | регресс после изменений | уровни 1–2 на тестовой задаче |

## Что внутри

| Каталог | Назначение |
|---|---|
| `mvp/` | доменный тулкит: `jira_client.py`, `gitlab_client.py`, `publish.py` (двухфазная публикация MR), `lint.py` (BSL Language Server, fail-closed), `envconfig.py`, `seed_demo.py` |
| `mvp/skills/1c-vibe-demo/` | скилл агента — пошаговая процедура «задача → ветка → правка → MR» |
| `mvp/demo-project/` | синтетическая 1С-выгрузка (XML+BSL) с CI-линтером для тренировки и проверок |
| `mvp/dump/` | рабочие клоны демо-репо (в git не попадает — песочница агента) |
| `mvp/tests/` | тесты тулкита (pytest) |
| `win/` | контурная цепочка 1С через `ibcmd` (restore .dt → import XML → check) — проверка правок на настоящей платформе 1С |
| `scripts/` | `cleanroom-dsh.sh` — «чистая комната»: свежий изолированный харнес для проверки глазами нового пользователя |
| `docs/` | онбординг, план MVP, хэндовер, исторические решения |

## Шпаргалка команд (из `mvp/`, через `uv run python3 …`)

```bash
gitlab_client.py whoami                                  # проверить GitLab-доступ
jira_client.py get INTAIDEV-1                            # прочитать задачу
jira_client.py search "labels = agent-run"               # найти задачи
publish.py INTAIDEV-2 --repo dump/1c-vibe-demo --prepare # подготовить ветку agent/INTAIDEV-2
publish.py INTAIDEV-2 "резюме" --repo dump/1c-vibe-demo  # коммит → push → MR → комментарий в Jira
lint.py --src dump/1c-vibe-demo                          # проверка BSL (fail-closed)
python3 -m pytest tests/ -q                              # тесты тулкита
```

## Правила безопасности

- Ключи и адреса — **только в `mvp/.env`** (не коммитится; шаблон:
  `mvp/.env.example`). Ключ модели — только в `~/.dsh/.credentials.yaml`.
- Агент публикует работу **только через MR из ветки `agent/<KEY>`**;
  основная ветка — только для людей.
- Необратимое (хранилище 1С, деплой, прод) — готовит агент, выполняет
  **человек**.
- Проверки и тренировки — только на **демо-проекте** и тестовых задачах.
- Корпоративный VPN нужен для доступа к Jira/GitLab/LiteLLM — держи его
  включённым на время работы (модель обращается к сети в момент запроса).

## Дорожная карта

- **MVP (готов):** Jira → ветка → правка → BSL-линт → MR → комментарий.
- **Тестовый контур 1С:** Windows-VM, `ibcmd`: restore ночного бэкапа →
  import XML → `/CheckConfig` (заготовки в `win/`).
- Далее: YAxUnit/Vanessa-автотесты, мост git→хранилище 1С в полуавтомате,
  GUI-петля для форм.
- **Переезд на платформу agctl** при её внедрении в ЦИТ (тулкит и скилл
  переезжают как есть).
